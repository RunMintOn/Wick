# LocalDeck 服务管理

LocalDeck 的控制台只负责展示和发送操作。Process Compose 管理本机服务，用户级 launchd 管理后台启动。退出控制台后服务继续运行。

将后台程序接入 LocalDeck，指的是登记启动信息并交给现有管理器运行；服务仍是本机进程，网页仍通过浏览器访问。

## 找到实际环境

此 Skill 随 LocalDeck 源码保存，安装时通过目录软链接供 Agent 发现。将系统给出的 Skill 所在目录赋给 `SKILL_DIR`，先解析真实目录，再定位项目：

```bash
PROJECT="$(cd -P "$SKILL_DIR" && cd ../.. && pwd -P)"
HOME_DIR="${LOCALDECK_HOME:-$HOME/Library/Application Support/LocalDeck}"
SOCKET="$HOME_DIR/control.sock"
PC="${LOCALDECK_PC:-/opt/homebrew/bin/process-compose}"
```

确认项目有 `package.json`，读取项目里的 `docs/agent-registration.md`。该操作文档是配置字段和现有命令的依据；保留现有服务和设置，只改本次任务涉及的内容。

完成条件：明确本次使用的项目、唯一配置文件、socket 与目标服务；涉及已有进程时，已查明实际 PID、命令、端口和数据位置。

## 按任务执行

### 登记一个新服务

1. 确认程序或启动脚本能在 macOS 本机运行，使用固定位置的程序、工作目录和数据。已有运行环境可以复用，例如项目里的 Python 虚拟环境。通过绝对路径启动，避免依赖某个终端的激活状态。
2. 检查目标端口是否被占用。已有服务的接管按下一节处理。
3. 在唯一配置的 `processes` 中增加稳定标识。依据操作文档填写启动信息和展示地址。登录自启默认关闭，用户要求时开启；不要把现有 YAML 转成另一份配置格式。
4. 在项目中执行校验，成功后应用。使用现有集成脚本，避免直接用源配置启动第二个管理器。
5. 用现有 CLI 启动目标服务，检查结构化状态、实际访问地址和近期日志。确认未修改服务的 PID 不变。

完成条件：目标服务由 LocalDeck 后台管理，实际入口可访问，程序与数据不依赖临时目录，其他服务未被重启。向用户说明打开方式和自启设置。

### 接管一个已经运行的进程

先读本 Skill 的 `references/takeover.md`。确认原进程的所有者、启动参数及数据，准备好新配置后再切换。仅停止已确认的目标实例。

完成条件：原实例已退出；目标端口只有一个已登记实例监听；有数据时完成必要的一致性检查；空实例不引入无意义的数据迁移。

### 日常操作

从操作文档选择现有 CLI 命令完成查询、启动、停止、重启和读取近期日志。无需打开控制台，也无需模拟 TUI 按键。

- 手动停止：只影响当前运行，不修改登录自启，不触发异常恢复。
- 修改登录自启：只影响下次后台启动，不立即启停服务。Agent 修改后按文档校验和应用。
- 异常恢复预算耗尽：先根据日志修复原因，再用现有恢复脚本或控制台 Start。普通原生 start 不会重置当前版本的耗尽计数。
- 打开网页：控制台的 Address 行提供 Open in Browser。它调用默认浏览器，不保证复用同网址的已有标签页。

完成条件：检查操作后的实际状态；停止时确认进程退出和端口释放，启动时确认入口可访问。涉及自启时，分别说明当前状态和持久设置。

### 排查后台连接与服务失败

顶部的 Connected / Connecting / Unavailable 表示后台连接，不表示服务健康。后台可连接但配置有错时，应保留 Connected，并单独显示配置错误。

1. 先尝试查询该 socket 的管理接口。能查询时，查看目标服务状态和日志；配置报错时检查源 YAML。
2. 不能查询时，检查用户级 launchd job 和最近的 bootstrap 日志。控制台 Reconnect 会重新连接，必要时按现有机制拉起后台。
3. 后台重新启动会按登录自启设置决定启动哪些服务。它不能保证恢复崩溃前的运行列表。
4. 端口冲突时重新核对监听进程。如果是旧实例残留，只在用户授权的目标范围内处理；不要用模糊进程名批量结束进程。

完成条件：明确是后台连接、配置、启动命令、端口还是服务本身的问题。只把实际完成的恢复和检查称为已验证。实际注销再登录与同会话的 launchd 启动验证分开记录。

### 移除登记或更新控制台

移除服务前先确认用户要停止服务还是连同登记一起移除。移除登记会影响该服务的运行；程序、依赖和数据默认保留。应用移除后确认其他服务未受影响。

更新控制台只重建和重新打开 App。比较更新前后的服务 PID 与访问情况，避免为了替换界面去停止整个后台。安装位置改变后，启动固定位置的 App 更新其后台启动路径。

完成条件：操作范围与用户要求一致；未授权的数据、程序和其他服务保持不动。报告最终状态，不把配置写入成功当作服务接入成功。
