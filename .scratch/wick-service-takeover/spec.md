# 已有服务接管与多进程服务

## 已确认决策

- 一个服务可以包含多个组成进程。首页按服务展示，详情展示进程、依赖、状态与日志。
- 支持整体和单个进程启停、重启，控制台和 Agent 使用相同语义。
- 启动自动满足依赖并等待就绪；依赖失败阻止下游，不影响独立分支。停止按依赖逆序，某个停止失败仍继续。
- 启动不是事务：保留已启动及原有进程，不回滚；重试只补齐缺失进程。整体重启明确停止再启动。
- 停止单个进程不连带停止其他进程；存在运行中的依赖方时确认影响。单独重启只重启目标，提示影响。
- 运行中故障有限重试，不连带停止；整体准确显示部分运行或异常。
- 每个服务一个登录自启开关，无组成进程级开关；下次后台启动（包括同会话重启）按依赖启动全部组成进程，不改变当前状态。
- Agent 完全负责接管，暂不做图形接管向导。查清 PID、命令、端口、数据、旧管理器、自启状态；展示并确认最终自启选择，明确要求保留原行为时不重复询问。旧进程自启不一致时明确选择整个服务的策略。
- 旧登记停用但默认保留恢复依据；失败停止推进、保留现场，不自动拉起旧实例。无必要不迁移数据，不覆盖或删除原有数据。
- 分别报告当前运行、自启及生效时机、旧管理器停用状态。命令 stderr 不等同失败，命令成功不等同服务就绪。
- 现有单进程登记继续可用；配置应用、自启变更、目标操作不重启未修改的服务。

## 验证

使用隔离配置与真实 Process Compose，经 ServiceManager / Agent CLI 和控制台边界验证；覆盖 HTTP 就绪、部分失败、重试、依赖逆序停止、自启后台重启、未修改服务 PID 保持。控制台使用隔离测试，不接管真实服务，不执行注销登录。
