# 真实 UI 取材

先确定采集边界：网页内容、嵌入式 WebView、完整应用窗口不是同一种素材。以下处理作用于外部产品的取材阶段，不是 HyperFrames 合成时间线的动画规则。

## 隐藏窗口的入场动画停在透明状态

**已观察：macOS 隐藏 WKWebView 的外部应用截图。** 元素存在、尺寸正常，但有限 CSS 入场动画没有推进：状态条的 `opacity` 停在 `0`、变换后高度约为 `1.4`；结束动画后恢复为 `opacity: 1`、高度 `4`。这不是所有平台的通用缺陷，也不能仅凭缺图就认定是同一原因。

1. 在修改产品代码前，比较正常运行图与采集结果，检查缺失元素的 DOM、计算样式和动画进度。
2. 若确认是有限入场动画停滞，且目标是静态的最终状态，在隔离采集页面中结束目标区域的有限动画。例如，`target` 是已定位的缺失组件：

   ```js
   target.getBoundingClientRect();
   for (const animation of target.getAnimations({ subtree: true })) {
     if (Number.isFinite(animation.effect.getComputedTiming().endTime)) {
       animation.finish();
     }
   }
   ```

3. 再次测量并截图，比较元素是否恢复、状态颜色是否对应当前数据。固定延时不能证明动画已经推进。

**完成标准：** 采集图和正常运行图中的目标组件外观一致，且没有为取材修改产品源码。

若目标是录制动画过程，改用能够推进该动画的采集方式；结束动画只适合静态终态。无限动画、视频和应用状态机也不属于这个处理范围。

## 网页截图没有原生窗口外壳

**已观察：WKWebView 内容捕获不包含 macOS 原生窗口按钮。** 其他平台先查当前采集接口的边界，不直接套用这个结论。

- 需要完整窗口时，优先使用能覆盖整个窗口的采集方式。
- 当前方式只能获取内容时，可以从有来源的真实运行图取得缺失外壳，在影片内合成。记录裁片来源和合成范围，保留原有功能状态。

**完成标准：** 目标窗口元素完整、比例和位置匹配真实运行图，且素材记录明确区分内容捕获与外壳合成。不要通过修改产品 UI 来掩盖采集边界。

## 完整窗口被误当成横向裁片

这是素材构图问题，不是采集 API 的版本缺陷。真实截图即使未重绘，裁掉下半部后也可能显得窗口过扁、底部被截断。先区分用户说的是视频画布比例，还是画布内产品窗口的比例。

- 展示完整窗口：沿用原图宽高比，空间不够就整体等比缩小，保留底部边界；不要为了填满横屏而裁底或非等比拉伸。
- 展示功能特写：可以局部裁切，但明确它是观察区域，不能把这条修正批量应用到所有特写。
- 转入下一镜头时，核对窗口位置、比例和功能状态；同一窗口的接场不应无意变形或跳状态。

**完成标准：** 所要求的完整窗口四边可见、比例与来源一致；有意的功能特写仍有效。
